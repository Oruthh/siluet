# Localization (I18N)

Siluet provides built-in support for internationalization (I18N), allowing you to easily build multi-language templates. Translations are stored in simple JSON files and accessed in your templates with the `t` filter.

## 1. Directory Structure

By default, Siluet looks for translation files inside a `locales/` directory at the root of your asset loader path (e.g., `src/main/resources/theme/locales/`).

Each file should be named according to its language code (e.g., `en.json`, `pl.json`, `es.json`).

```text
resources/theme/
├── locales/
│   ├── en.json         # English translations
│   └── pl.json         # Polish translations
├── templates/
├── sections/
└── components/
```

## 2. Translation Dictionaries (JSON)

Inside your locale files, you can structure your translations using nested JSON objects. This keeps your translations organized by feature, component, or page.

**Example `locales/en.json`:**
```json
{
  "store": {
    "welcomeMessage": "Welcome to Siluet Tech Store!",
    "actions": {
      "addToCart": "Add to Cart",
      "checkout": "Proceed to Checkout",
      "viewDetails": "View Details"
    }
  },
  "errors": {
    "outOfStock": "This item is currently out of stock."
  }
}
```

### Key Flattening
When Siluet loads these JSON files, it **flattens** the nested structure into dot-notation keys. This means you don't have to write complex object traversals in your templates.

For example, the nested path `"store" -> "actions" -> "addToCart"` simply becomes the string key `"store.actions.addToCart"`.

## 3. Using Translations in Templates

To print a translation, pass the flattened dot-notation key to the `t` filter inside <span v-pre>`{{ }}`</span>:

```html
<!-- components/productCard.html -->
<article class="product-card">
    <div class="card-body">
        <h3>{{ item.name }}</h3>

        @if(item.inStock) {
            <button class="btn-primary">
                {{ "store.actions.addToCart" | t }}
            </button>
        } @else {
            <p class="error-text">
                {{ "errors.outOfStock" | t }}
            </p>
        }
    </div>
</article>
```

Because `t` is a regular filter, it works everywhere <span v-pre>`{{ }}`</span> works, including HTML attributes:

```html
<input type="search" placeholder="{{ "search.hint" | t }}" aria-label="{{ "search.label" | t }}">
```

The key does not have to be a literal. It can come from your model or section properties, and the result can be passed to other filters:

```html
<span class="badge">{{ item.statusKey | t }}</span>
<h2>{{ "store.welcomeMessage" | t | uppercase }}</h2>
```

If a key is missing from the active locale file, the key itself is printed (e.g. `store.actions.addToCart`), which makes missing translations easy to spot. The key must be a string; any other value fails the render with an error pointing at the filter.

### Escaping

Translations are HTML-escaped by default, just like any other value printed with <span v-pre>`{{ }}`</span>. This applies both to the `t` filter and to `t:` properties defined in template configuration. Characters such as `<`, `>`, `&`, `"` and `'` are rendered as text, so a translation cannot inject markup or scripts into the page, and it is safe to use inside HTML attributes:

```html
<!-- If "search.hint" is: Search "shoes" & more -->
<input placeholder="{{ "search.hint" | t }}">
<!-- Renders: <input placeholder="Search &quot;shoes&quot; &amp; more"> -->
```

Because `t` is a regular filter, a translation can be passed to `rawHTML` to print it without escaping: <span v-pre>`{{ "key" | t | rawHTML }}`</span>. Do this only for locale files you fully trust. In most cases it is better to keep markup in your templates and only plain text in locale files. If a sentence needs a link or emphasis, split it into separate keys:

```json
{
  "checkout": {
    "terms": {
      "prefix": "I accept the",
      "link": "terms and conditions"
    }
  }
}
```

```html
<p>{{ "checkout.terms.prefix" | t }} <a href="/terms">{{ "checkout.terms.link" | t }}</a></p>
```

## 4. Configuring the Render Context

Siluet determines which translation file to load based on the `Locale` provided to the render context in your Kotlin code. If you request `Locale.ENGLISH`, Siluet will attempt to resolve translations from `locales/en.json`.

```kotlin
import dev.siluet.Siluet
import dev.siluet.loader.ResourceSiluetAssetLoader
import java.util.Locale

fun main() {
    val siluet = Siluet {
        assetLoader = ResourceSiluetAssetLoader("theme")
    }

    val model = mapOf("name" to "Wireless Mouse")

    // Rendering with English locale (uses locales/en.json)
    val englishOutput = siluet.render("product", model) {
        locale = Locale.ENGLISH
    }

    // Rendering with Polish locale (uses locales/pl.json)
    val polishOutput = siluet.render("product", model) {
        locale = Locale.of("pl", "PL")
    }
}
```
